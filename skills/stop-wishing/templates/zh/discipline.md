# 纪律与接手清单（discipline）

> 最后更新：YYYY-MM-DDTHH:mm±HH:MM（ISO 8601，含本机时区偏移）
> 本文件是 `SKILL.md` §9「硬约束」的副本 + 接手清单；两份不一致时以 `SKILL.md` 为准。

## 一、硬约束（逐条照做）

1. **禁硬编码**：绝对路径、密钥、魔法数字（阈值/超时/端口）、URL、端口、模型名 → 配置/环境变量/命名常量；脚本默认值必须可被参数覆盖。
2. **时间戳**：`YYYY-MM-DDTHH:mm±HH:MM`，只写在**文件头改动块**与 `docs/progress.md`。
3. **禁全量重写**：单文件 diff > 50% 或 > 300 行，必须先说明并获批。
4. **搜索留痕**：搜过什么、结论、许可证，写进 `progress.md`。
5. **不可逆操作必须人批**：删文件/删目录、改数据库、`git reset --hard`、覆盖未备份配置、装到系统目录、重启服务。
6. **不扩大范围**：没要求的重构/格式化/依赖升级，不做。

## 二、动手前检查（每次）

- [ ] 我报了档位（轻/中/重）与原因？
- [ ] 需求卡七字段（含「明确不做」）确认过？
- [ ] 搜过现成实现？许可证过闸（含字体/图标/API/模板）？
- [ ] 先解释了「改什么/影响/风险/怎么退」，并等到确认？
- [ ] 备份打好（tag 或 `.bak-YYYYMMDD-HHmm`）？
- [ ] 改动是最小差异？

## 三、交付前检查（每次）

- [ ] 验证命令跑过，原始输出贴出（三列表：断言｜证据｜来源）？
- [ ] 更新了 `project.md`（如需）/`progress.md`/`todo.md`？
- [ ] 未验证项明确写成「未验证 / 未知」？
- [ ] 没有把密钥/本机路径写进仓库？

## 四、接手清单（新人第一天）

1. 读 `docs/project.md`（要做什么）、`docs/structure.md`（东西在哪）；
2. 读本文件（规矩）与 `docs/progress.md` 的时间线（已经踩过什么坑）；
3. 跑一次 `node scripts/check-env.js`（本机有什么、建议怎么备份）；
4. 跑一次 `node scripts/check-hardcode.js`（当前仓库有没有正在扩散的硬编码）；
5. 按 `docs/todo.md` 的「现在做」拿第一条，动手前照第二节自检。

## 五、失败处理

- 同一问题最多 3 次；3 次不过 → 停下升级给人（说清试了什么、错误原文、怀疑的 3 个可能、需要什么决定）；
- 不猜密钥、不关校验、不绕过测试、不删证据。

## 六、术语补充（4 条最容易混的）

| 术语 | 一句人话 | 会影响什么 |
|---|---|---|
| 传染性许可证 | 用了它，你的代码也可能被迫按它的许可证开源 | 商用闭源能不能用（GPL/AGPL 一律不行，LGPL 本 skill 也从紧拒绝） |
| 动态链接 | 运行时才调用别人的库，不把代码拷进你的程序 | LGPL 的适用空间（法理有空间，本 skill 为省事仍拒绝） |
| 衍生作品 | 基于别人代码改出来的东西，法律上算它的「孩子」 | 开源义务的范围（GPL 要求整个衍生作品同许可） |
| 回归测试 | 改完再跑一遍老测试，确认没弄坏旧功能 | 这次改动敢不敢合并（§三 交付前检查） |
