最容易搞混的 10 组词

这些不是"再记一遍"，而是新手最常张冠李戴的地方。

Token vs Token
词元是 AI 算钱和算记忆长度的单位（一个汉字约 1–2 个）；令牌是一串登录凭证（ghp_ 开头那种）。同一个词，两个完全无关的意思。
Git vs GitHub
Git 是装在你电脑上的工具，负责记录改动；GitHub 是一个网站，用来托管这些记录并和别人协作。像"Word"和"网盘"的关系。
前端 vs 后端
前端是用户看得见、点得到的（按钮、页面）；后端是用户看不见、在服务器上算的（存数据、校验密码）。
框架 vs 库
框架规定好结构，你往里填（它调用你）；库是你随时拿来用（你调用它）。
API vs SDK
API 是点菜的窗口（约定怎么问、会得到什么）；SDK 是打包好的工具包，把点菜流程封装成一键操作。
认证 vs 授权
认证是确认你是谁（登录）；授权是确认你能干什么（有没有权限删别人的帖子）。先认证，再授权。
构建 vs 部署
构建是把源码加工成能跑的文件（面粉→面包）；部署是把成品放到服务器上让人访问（面包→上架）。
Localhost vs 线上
Localhost 是你自己这台电脑，只有你能打开；线上是放到公网服务器，谁都能访问。
Prompt vs Context
Prompt 是你这一句新说的话；Context 是模型这次能看到的全部内容，包括之前所有对话和你贴的代码。
Bug vs 报错
Bug 是代码本身的毛病（可能不报错，只是结果不对）；报错是程序跑不下去时喊出来的信号。有 Bug 不一定报错，报错一定有原因。

新手最常踩的 5 个坑

  1. 把 API Key 写进前端代码。前端代码任何人都能在浏览器里看到，等于把密码贴在门口。密钥要放后端或环境变量（.env）。
  2. 只说"帮我优化一下"。没有验收标准，AI 只能猜。改成"首屏加载从 3 秒降到 1 秒以内，其他功能不许变"。
  3. 一次让 AI 改十个地方。改坏了你不知道是哪一步坏的，也没法回退。一次一个小目标，改完立刻验证。
  4. 不 commit 就让 AI 大改。Commit 是存档。没有存档，AI 把文件改烂了就只能重来。
  5. 报错只说"用不了"。把完整报错、你做了什么、期望什么一起给 AI。信息越全，它猜对的概率越高。
